# Android client (Capacitor)

The Android app is the same web client wrapped in a fullscreen Capacitor
WebView. There is **no separate mobile codebase** — every gameplay/UI change
lands in `src/` and ships to the app by rebuilding the bundle and re-syncing.

## What the native shell adds

- Fullscreen immersive mode (status/nav bars hidden, swipe from the edge to
  peek them) — `android/app/src/main/java/com/mbplanes/app/MainActivity.java`.
- `sensorLandscape` orientation lock (both landscape directions, no portrait).
- Screen never sleeps (`FLAG_KEEP_SCREEN_ON`).
- Edge-to-edge rendering under display cutouts; the web layout pads itself
  with `env(safe-area-inset-*)` (see the touch CSS in `index.html`).
- Launcher icon + splash: gold plane on navy, all vector
  (`res/drawable/ic_launcher_plane.xml`, `launch_splash.xml`).

## Multiplayer server

In the WebView the page origin is useless for deriving the relay address, so
the native build connects straight to `NATIVE_MP_URL` in `src/config.js`
(`wss://mbplanes.com/ws`). The `?server=` override still wins if you ever load
the app with a custom URL. Detection: `window.Capacitor.isNativePlatform()` in
`defaultServerUrl()` (`src/main.js`).

## Building an APK

Prereqs on this machine (all via Homebrew): `openjdk@21`,
`android-commandlinetools` (build-tools 35, platform android-35+),
`android-platform-tools`. Gradle comes from the checked-in wrapper.

```bash
npm run build                 # fresh dist/
npx cap sync android          # copy dist/ into the native project
cd android
JAVA_HOME=/opt/homebrew/opt/openjdk@21 \
ANDROID_HOME=/opt/homebrew/share/android-commandlinetools \
./gradlew assembleRelease     # or assembleDebug
```

Outputs: `android/app/build/outputs/apk/release/app-release.apk` (signed,
give this one to testers) and `.../debug/app-debug.apk`.

## Signing

`android/keystore.properties` + `android/keystore/mbplanes-release.keystore`
hold the release key. **Both are gitignored — back them up.** If this key is
ever lost, a Google Play listing made with it can never be updated again
(uploading to Play for the first time: opt into Play App Signing and this
becomes the upload key). Losing it before the first Play upload only costs
testers a reinstall (signature mismatch on update).

## Versioning

`versionCode`/`versionName` in `android/app/build.gradle` mirror
`GAME_VERSION` in `src/config.js`: `versionCode = major*10000 + minor*100 +
patch` (1.2.2 → 10202). Bump both together with every release —
Android refuses to update to an APK whose versionCode didn't grow.

## Gotchas

- `android/app/src/main/assets/public/` is generated by `cap sync` and
  gitignored — a fresh clone must run `npm run build && npx cap sync android`
  before the first Gradle build.
- The touch UI itself is plain web code (`src/ui/Touch.js`, touch CSS block in
  `index.html`) — test it in a desktop browser with `?touch=1`, no device
  needed for layout work.
